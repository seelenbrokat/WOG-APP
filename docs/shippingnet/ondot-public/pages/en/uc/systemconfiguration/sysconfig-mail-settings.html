Setting up OAuth2 authentication for Microsoft 365

OAuth2 authentication is required to send mail via Microsoft 365 accounts. Microsoft has set a transition period for existing calls until September 2025, from which Basic authentication will be generally disabled.

To use OAuth2, application registration in the Microsoft Entra Admin Center and rights assignment for mailboxes by an administrator are required.

Configuration

1. Application Registration

1.1 Signing in to Microsoft Entra Admin Center

1.2 Under Identity>Applications>App Registrations, select New Registration.

1.3 Give it any name, e.g. shippingNET Mailversand and complete the registration

2. Permissions

2.1 Add permission

2.1 The SMTP. Assign SendAsApp

2.3 Granting Administrator Consent

3. Connect Exchange mailboxes

3.1 Connect to Powershell
Mailboxes can be linked to the newly registered app using Powershell commands. To do this, you need the Tenant ID (technically Tenant ID) from the Entra Admin Center Home

Start Powershell as administrator and insert the Tenant ID

Install-Module -Name ExchangeOnlineManagement
Import-module ExchangeOnlineManagement 
Connect-ExchangeOnline -Organization <Mandanten-ID>

3.2 Registering the Application as a Principal in Exchange
Registration requires the Application ID and Object ID of the newly registered app from the Enterprise Applications perspective.

Paste the IDs in Powershell

New-ServicePrincipal -AppId <Anwendungs-ID> -ObjectId <Objekt-ID>

3.3 Granting permission for sender mailboxes
Allow any mailbox that is used as an email sender in shippingNET for the app via Powershell (replace address and object ID)

Add-MailboxPermission -Identity "beispielabsender@beispieladresse.at" -User <Anwendungs-ID> -AccessRights FullAccess

4. Configuration in shippingNET

To configure in shippingNET, you need the Application ID (Client) and OAuth 2.0 token endpoint (v2), which can be found in the application's overview page in Entra:

In addition, authentication requires a **Secret Client Key (Secret), which must be generated for the application. The value is only visible immediately after creation and must therefore be copied immediately:

Tip

The client secret key has a maximum validity of 2 years and must therefore be renewed regularly. Instead, a certificate generated by shippingNET can be stored, which enables a much longer validity.

Enter the 3 values in the fields Token Endpoint, Application ID and Secret in the email settings in shippingNET

Note

Full OAuth configuration is only supported starting with shippingNET version 25.2. In older versions, other fields can be used for this:

  • Username: Application ID (Client)
  • Password: Secret Client Key (Secret)
  • Domain: OAuth 2.0 token endpoint (v2)

certificates cannot be used in old versions
