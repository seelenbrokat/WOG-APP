Archive data

Over time, the amount of data stored in any software solution grows continuously – whether through daily business processes, system logs or user activities. This growing amount of data can have a negative impact on the performance and stability of the system.

To ensure consistently high system performance and efficient data management, it is recommended to set up data archiving in shippingNET. Older data from the active database is moved to a separate archive. In this way, the system remains performant, the database size is reduced and at the same time historical information remains available, for example for evaluations or legal obligations to provide evidence.

Data archiving is therefore a central component of sustainable system maintenance and makes a significant contribution to optimizing the overall performance and maintainability of the application.

Note

This feature is available in version 26.1 or later.

How it works

The data is archived by a database job in the maintenance window. This job must call the stored procedure spMaintenanceArchiveMain.

This stored procedure is the main procedure that calls the respective specific procedures depending on the topic (ordering, shipping, etc.). There are intentionally no transactions, the transactions are exclusively in the sub-procedures.

  • The transaction data that is older than the cutoffDate is archived. The cutoffDate is calculated using the monthToKeep parameter. It is advisable not to get closer than 6 months to the current date, otherwise relevant transaction data could be deleted.
  • The maximum number of records to be deleted is set in the batchSize parameter. The batchSize must not be too large, otherwise the transaction will run too long. The batchSize only defines the number of records of the main entity (shipments or orders). Dependent entities are automatically archived as well.
  • Set the maximum runtime with the maxDurationSeconds parameter. The process calls the subprocedures in a loop until the maximum runtime has elapsed.
  • To delete the data, set the mode parameter to "delete". By default, the data is moved to the archive (mode=archive).
  • The name of the archive DB must be specified in the system variables.

The process will be aborted if:

  • no data could be deleted, or
  • the maxDurationSeconds have elapsed (for the entire process), or
  • too many deadlocks (maxRetries)
Warning

The archive database must be located on the same database server as the production database.

Access to the archive

Web App

To access the data in the archive, you need to switch the web app to archive mode:

  1. In the navigation bar, click the gear icon .
  2. In the General section, you can enable or deactivate archive mode.
Note

Physically a data record is either in the archive or in the production database! However, archive mode displays the combined data from the production and archive databases. Data is provided via database views that combine both data sources.

Saving data is not possible in archive mode!

Power BI Reporting

The archive tables are provided separately for Power BI reporting. Since the data in the archive can no longer be changed, you can use the ArchiveDate field for synchronization with the Microsoft Power BI service and thus only load the last day at a time. This significantly reduces the volume of data transferred.
